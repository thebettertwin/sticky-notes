# Architecture

The app is organised by feature: `sticky-note`, `note-placement`, `notes-board`, `notes-toolbar`, `trash-note` and `colour-picker`, plus `core-ui` for pieces that know nothing about notes (`Button`, `IconButton`, `Toolbar`, `ToolbarDock`, design tokens and geometry helpers). `App` is the composition root. It owns the short-lived UI state (the active note, the selected colour and whether a note is being placed) and connects the board to the toolbar, plus the board's pan offset (`useBoardPan`). Note data lives in a single `useReducer` behind the `useNotes` hook, whose actions are `add`, `update`, `remove` and `bringToFront`. The rules that don't need React are kept in plain TypeScript modules: the reducer, local storage loading and validation (`noteStorage`), hit-testing (`isPointInRect`) and placement maths (`rectFromPoints`). These modules hold the logic that matters and are unit tested with Vitest, while the components stay thin.

Interactions are built on browser primitives rather than libraries. Moving a note uses pointer events with pointer capture on the note's top strip. Creating a note puts a temporary `PlacementLayer` over the board, which shows a ghost note under the cursor and turns a click into a default-sized note or a drag into a rectangle. Resizing uses the browser's native resize grip, and a `ResizeObserver` writes the new size back to state. The trash zone is checked by comparing the pointer position with the trash's bounding box (`useTrashZone`), so it works whatever is drawn on top of it. The board is an unbounded canvas: notes are stored in board coordinates inside a world layer that's offset by the pan, and the board pans with the trackpad, the mouse wheel (converting Firefox's line-based deltas to pixels) or by dragging empty space. Dragging a note measures from the world layer, which already includes the pan, and the placement layer converts its viewport coordinates to board coordinates by adding the pan. The world is offset with `left`/`top` rather than `transform`, because a transform would create a stacking context that keeps a dragged note below the toolbar. Keyboard users can add notes and can delete a focused note with Delete.

Performance comes mostly from preserving object identity. `StickyNote` is memoised, its callbacks take the note's id so the same stable functions are passed to every note, and the reducer only creates a new object for the note that changed. A drag therefore re-renders only the note being dragged. The placement ghost keeps its position in local state, so moving the cursor while placing only re-renders the placement layer, and the trash only re-renders when the pointer crosses its edge. Saving to local storage is debounced by 300ms, with a final save when the page is closed. The storage key is versioned, and loaded data is validated note by note, so malformed entries are dropped instead of breaking the app. Styling is plain CSS using design tokens (custom properties) in `tokens.css`, sized in rem, with light and dark themes. The selected note's folded corner uses CSS `corner-shape` where the browser supports it, with an outline as the fallback.
